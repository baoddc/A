# Implementation Plan: Lưu Trữ Dữ Liệu Quét Kiểm Kê Trên Supabase & Phân Quyền Xóa Độc Quyền Cho User "bao.lt"

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chuyển đổi cơ chế lưu trữ quét kiểm kê từ LocalStorage sang Supabase tập trung (`kiem_ke_scans`) với khả năng đồng bộ thời gian thực (Realtime), đồng thời thiết lập bảo mật 2 lớp chỉ cho phép duy nhất tài khoản `bao.lt` có quyền xóa một phần (từng cuộn) hoặc xóa toàn bộ dữ liệu quét.

**Architecture:** Sử dụng kiến trúc Optimistic UI kết hợp Supabase REST API và Realtime Channel trên `KiemKeStorage`. Tại frontend và backend RLS, áp dụng cơ chế xác thực kép để kiểm tra định danh `bao.lt` trước khi thực hiện bất kỳ hành động xóa nào.

**Tech Stack:** Vanilla JavaScript (ES6+), HTML5, Bootstrap 5, Supabase JS SDK v2, PostgreSQL (RLS), Node.js (test runner).

## Global Constraints

- Không làm gián đoạn tốc độ quét: việc quét phải phản hồi tức thì bằng âm thanh Beep và đưa lên giao diện ngay lập tức (Optimistic UI), không chờ request mạng hoàn tất mới hiển thị.
- Mọi tài khoản khác ngoài `bao.lt` (kể cả guest hay tài khoản có quyền xem/thêm) đều bị ẩn toàn bộ các nút xóa và bị chặn hoàn toàn nếu cố tình gọi hàm xóa.
- Sau khi hoàn thành phải chạy `npm run build` (`node scripts/sync-dist.js`) để đồng bộ code sang `dist/`, `dist-app/`, `public/`.

### Task 1: Tạo Script SQL Cài Đặt Bảng `kiem_ke_scans` & RLS Policies

**Files:**
- Create: `scripts/setup_kiem_ke_scans.sql`

**Interfaces:**
- Produces: Bảng `public.kiem_ke_scans` với các trường `id`, `barcode`, `ma_vat_tu`, `batch`, `kg`, `scanned_by`, `created_at` và RLS policies.

- [ ] **Step 1: Viết script SQL `scripts/setup_kiem_ke_scans.sql`**

Nội dung script:
```sql
-- =============================================================================
-- SCRIPT CÀI ĐẶT BẢNG LƯU TRỮ QUÉT KIỂM KÊ VÀ PHÂN QUYỀN RLS TRÊN SUPABASE
-- Hướng dẫn: Mở Supabase Dashboard -> SQL Editor -> Dán nội dung và bấm Run
-- =============================================================================

CREATE TABLE IF NOT EXISTS public.kiem_ke_scans (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    barcode TEXT NOT NULL,
    ma_vat_tu TEXT NOT NULL,
    batch TEXT DEFAULT '',
    kg NUMERIC DEFAULT 0,
    scanned_by TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_kiem_ke_scans_barcode ON public.kiem_ke_scans(barcode);
CREATE INDEX IF NOT EXISTS idx_kiem_ke_scans_created_at ON public.kiem_ke_scans(created_at DESC);

-- Bật Row Level Security (RLS)
ALTER TABLE public.kiem_ke_scans ENABLE ROW LEVEL SECURITY;

-- 1. Cho phép tất cả người dùng (authenticated & anon) đọc danh sách quét
DROP POLICY IF EXISTS "Allow read kiem_ke_scans" ON public.kiem_ke_scans;
CREATE POLICY "Allow read kiem_ke_scans" ON public.kiem_ke_scans
    FOR SELECT USING (true);

-- 2. Cho phép mọi người dùng ghi nhận cuộn đã quét
DROP POLICY IF EXISTS "Allow insert kiem_ke_scans" ON public.kiem_ke_scans;
CREATE POLICY "Allow insert kiem_ke_scans" ON public.kiem_ke_scans
    FOR INSERT WITH CHECK (true);

-- 3. Chỉ DUY NHẤT tài khoản bao.lt mới có quyền XÓA cuộn hoặc xóa phiên quét
DROP POLICY IF EXISTS "Only bao.lt can delete kiem_ke_scans" ON public.kiem_ke_scans;
CREATE POLICY "Only bao.lt can delete kiem_ke_scans" ON public.kiem_ke_scans
    FOR DELETE USING (
        public.is_admin() = true
        OR LOWER(auth.jwt() ->> 'email') = 'thaibao06061997@gmail.com'
        OR LOWER((SELECT username FROM public.user_profiles WHERE id = auth.uid())) = 'bao.lt'
    );
```

```javascript
const assert = require('assert');

// Giả lập logic canUserDeleteKiemKe
function canUserDeleteKiemKe(mockProfile, mockCurrentUser) {
  if (mockProfile && (mockProfile.is_admin || String(mockProfile.username || '').toLowerCase() === 'bao.lt')) {
    return true;
  }
  if (mockCurrentUser && String(mockCurrentUser).trim().toLowerCase() === 'bao.lt') {
    return true;
  }
  return false;
}

// Test cases
console.log('Testing canUserDeleteKiemKe()...');

// 1. User bao.lt trong profile -> true
assert.strictEqual(canUserDeleteKiemKe({ username: 'bao.lt', is_admin: false }, null), true, 'bao.lt profile must return true');

// 2. User bao.lt trong currentUser localStorage -> true
assert.strictEqual(canUserDeleteKiemKe(null, 'bao.lt'), true, 'bao.lt in localStorage must return true');

// 3. User có is_admin = true -> true
assert.strictEqual(canUserDeleteKiemKe({ username: 'admin_test', is_admin: true }, null), true, 'admin must return true');

// 4. User khác -> false
assert.strictEqual(canUserDeleteKiemKe({ username: 'kho_xg', is_admin: false }, 'kho_xg'), false, 'other user must return false');
assert.strictEqual(canUserDeleteKiemKe(null, null), false, 'guest / null must return false');

console.log('All permission tests passed successfully!');
```
