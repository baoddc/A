## 1. Mục tiêu & Bối cảnh

Trước đây, trang `kiem-ke.html` chỉ lưu trữ danh sách cuộn quét trong bộ nhớ `localStorage` cục bộ của từng thiết bị. Điều này gây ra hạn chế:
1. Khi nhiều thủ kho hoặc công nhân cùng quét bằng điện thoại/máy quét tại các vị trí khác nhau, dữ liệu không thể gộp chung lại để đối soát toàn kho.
2. Bất kỳ ai mở trang cũng có thể bấm xóa cuộn hoặc xóa toàn bộ dữ liệu quét.

**Mục tiêu mới**:
1. **Lưu trữ tập trung trên Supabase**: Mọi user khi quét (qua Barcode scanner hoặc Camera) sẽ lập tức lưu trữ dữ liệu cuộn vào bảng `kiem_ke_scans` trên Supabase.
2. **Đồng bộ thời gian thực (Realtime)**: Hỗ trợ đa thiết bị cùng quét đồng thời, màn hình tự động cập nhật cuộn mới và bảng đối soát 3 chiều.
3. **Phân quyền xóa độc quyền cho `bao.lt`**: Chỉ duy nhất tài khoản `bao.lt` mới có quyền xóa 1 phần (xóa từng cuộn) hoặc xóa toàn bộ (làm lại phiên kiểm kê). Mọi user khác đều bị ẩn nút xóa và bị chặn hoàn toàn ở cả tầng giao diện lẫn cơ sở dữ liệu.

## 2. Thiết kế Cơ sở dữ liệu & RLS (Supabase)

### 2.1. Schema Bảng `public.kiem_ke_scans`
Tạo bảng mới `public.kiem_ke_scans` lưu trữ từng lượt quét cuộn:
```sql
CREATE TABLE IF NOT EXISTS public.kiem_ke_scans (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    barcode TEXT NOT NULL,
    ma_vat_tu TEXT NOT NULL,
    batch TEXT DEFAULT '',
    kg NUMERIC DEFAULT 0,
    scanned_by TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

- Các chỉ mục tăng tốc truy vấn:
  ```sql
  CREATE INDEX IF NOT EXISTS idx_kiem_ke_scans_barcode ON public.kiem_ke_scans(barcode);
  CREATE INDEX IF NOT EXISTS idx_kiem_ke_scans_created_at ON public.kiem_ke_scans(created_at DESC);
  ```

### 2.2. Chính sách Bảo Mật Row Level Security (RLS)
Bật RLS để bảo vệ dữ liệu ở tầng cơ sở dữ liệu:
```sql
ALTER TABLE public.kiem_ke_scans ENABLE ROW LEVEL SECURITY;

-- 1. Cho phép tất cả người dùng (authenticated & anon) đọc dữ liệu quét để đối soát chung
DROP POLICY IF EXISTS "Allow read kiem_ke_scans" ON public.kiem_ke_scans;
CREATE POLICY "Allow read kiem_ke_scans" ON public.kiem_ke_scans
    FOR SELECT USING (true);

-- 2. Cho phép mọi user ghi nhận cuộn đã quét
DROP POLICY IF EXISTS "Allow insert kiem_ke_scans" ON public.kiem_ke_scans;
CREATE POLICY "Allow insert kiem_ke_scans" ON public.kiem_ke_scans
    FOR INSERT WITH CHECK (true);

-- 3. Chỉ DUY NHẤT tài khoản bao.lt (hoặc admin) mới có quyền XÓA cuộn hoặc xóa toàn bộ
DROP POLICY IF EXISTS "Only bao.lt can delete kiem_ke_scans" ON public.kiem_ke_scans;
CREATE POLICY "Only bao.lt can delete kiem_ke_scans" ON public.kiem_ke_scans
    FOR DELETE USING (
        public.is_admin() = true
        OR LOWER(auth.jwt() ->> 'email') = 'thaibao06061997@gmail.com'
        OR LOWER((SELECT username FROM public.user_profiles WHERE id = auth.uid())) = 'bao.lt'
    );
```
Script hoàn chỉnh được lưu tại `scripts/setup_kiem_ke_scans.sql`.

## 3. Kiến Trúc Lưu Trữ & Đồng Bộ (`kiem-ke-storage.js`)

Mở rộng module `KiemKeStorage` để hỗ trợ tích hợp Supabase với LocalStorage fallback:

### 3.1. Các hàm API của `KiemKeStorage`
1. `fetchScannedRollsFromSupabase()`:
   - Truy vấn toàn bộ danh sách quét từ bảng `kiem_ke_scans`, sắp xếp theo `created_at DESC`.
   - Trả về danh sách chuẩn hóa `{ id, barcode, maVatTu, batch, kg, timestamp, scannedBy }`.
   - Đồng bộ vào LocalStorage để làm cache dự phòng.
2. `insertScannedRollToSupabase(rollItem)`:
   - Gửi `supabase.from('kiem_ke_scans').insert({ barcode, ma_vat_tu, batch, kg, scanned_by, created_at })`.
   - Trả về bản ghi đã chèn kèm `id` thực từ database.
3. `deleteScannedRollFromSupabase(id)`:
   - Gửi `supabase.from('kiem_ke_scans').delete().eq('id', id)`.
4. `clearAllScannedFromSupabase()`:
   - Gửi `supabase.from('kiem_ke_scans').delete().neq('id', 0)`.
5. `subscribeRealtimeChanges(onInsertCallback, onDeleteCallback)`:
   - Lắng nghe kênh `supabase.channel('kiem_ke_scans_changes')`.
   - Khi có `INSERT` từ client khác: kích hoạt callback cập nhật danh sách.
   - Khi có `DELETE` từ client khác: kích hoạt callback loại bỏ cuộn tương ứng.

## 4. Kiểm Soát Phân Quyền Xóa (Frontend Guard)

### 4.1. Hàm nhận diện quyền xóa `canUserDeleteKiemKe()`
Kiểm tra xem người dùng hiện tại có phải là `bao.lt` hay không:
```javascript
function canUserDeleteKiemKe() {
  const profile = typeof window.getCachedUserProfile === 'function' ? window.getCachedUserProfile() : null;
  if (profile && (profile.is_admin || String(profile.username).toLowerCase() === 'bao.lt')) {
    return true;
  }
  const currentUser = (typeof localStorage !== 'undefined' && localStorage.getItem('currentUser')) || (typeof window !== 'undefined' && window.currentUser);
  return !!(currentUser && String(currentUser).trim().toLowerCase() === 'bao.lt');
}
```

### 4.2. Ẩn / Hiện các phần tử xóa trên giao diện
1. **Nút Làm Lại (`#btnResetSession`)** trên Top Bar:
   - Thêm kiểm tra: Nếu `!canUserDeleteKiemKe()`, ẩn nút này (`d-none`).
2. **Nút Đặt Lại Danh Sách (`#btnClearFeedOnly`)** ở Tab 2:
   - Nếu `!canUserDeleteKiemKe()`, ẩn nút này (`d-none`).
3. **Cột Thao Tác Xóa trong Tab 2 (`#scannedRollsTableBody`)**:
   - Khi render danh sách cuộn: Nếu `!canUserDeleteKiemKe()`, không hiển thị nút xóa (hoặc ẩn cột Xóa).
4. **Bảo vệ Modal Xác Nhận Reset (`#resetConfirmModal`)**:
   - Nếu user không phải `bao.lt` cố tình kích hoạt modal hoặc các nút bên trong (`#btnResetAll`, `#btnResetScannedOnly`), hệ thống hủy ngay lập tức và hiển thị Toast cảnh báo: `"Chỉ tài khoản bao.lt mới có quyền xóa dữ liệu kiểm kê!"`.

1. Đăng nhập với tài khoản `bao.lt`:

3. Chạy `npm run build` để đồng bộ toàn bộ file đã sửa sang `dist/`, `dist-app/`, `public/`.
